# نشر Mabee3at على Render — الطبقة المجانية

> **تحذير قبل أي شيء:** قاعدة PostgreSQL المجانية على Render **تنتهي بعد ٣٠ يوماً
> من إنشائها**، ثم مهلة ١٤ يوماً للترقية، وبعدها **تُحذف هي وكل بياناتها نهائياً**.
> العدّاد يبدأ من لحظة الإنشاء لا من آخر استخدام. لا نسخ احتياطي ولا PITR
> على الطبقة المجانية. هذه بيئة تجريبية مؤقتة فقط، وليست إنتاجاً.

## ما تحتاجه

- حساب Render مجاني (لا يطلب بطاقة للطبقة المجانية)
- مستودع Git يحتوي هذا المشروع

## الخطوات

1. ارفعي المشروع إلى مستودع GitHub خاص.
2. في Render: **New → Blueprint**، واختاري المستودع.
   يقرأ Render ملف `render.yaml` وينشئ خدمتين **مجانيتين**:
   - `mabee3at-staging` — خدمة ويب (Free)
   - `mabee3at-staging-db` — PostgreSQL (Free)
3. تأكّدي أن كليهما مكتوب أمامهما **Free** قبل الضغط على Apply.
4. بعد أول نشر ناجح، افتحي الرابط:
   `https://mabee3at-staging.onrender.com/setup`
   وأنشئي حساب المدير الأول. الصفحة تتعطّل تلقائياً بعده.

### بيانات تجريبية (اختياري)

من **Shell** في لوحة Render:

```bash
MABEE3AT_ALLOW_RESEED=1 python app/seed.py
```

ينشئ حسابات عرض `admin` / `accountant` / `rep1` / `rep2` بكلمة `123456`.
**للعرض فقط.** لإظهار تلميح الحسابات في شاشة الدخول اضبطي `MABEE3AT_DEMO=1`.

## متغيّرات البيئة

| المتغيّر | المصدر | ملاحظة |
|---|---|---|
| `MABEE3AT_DB_URL` | يربطه Render من القاعدة | لا يُكتب يدوياً |
| `SECRET_KEY` | `generateValue: true` | يولّده Render، غير ظاهر في المستودع |
| `MABEE3AT_ENV` | `cloud` | يفعّل كوكيز HTTPS وإخفاء الأخطاء |
| `MABEE3AT_POOL_MAX` | `5` | القاعدة المجانية محدودة الاتصالات |
| `MABEE3AT_DEMO` | اختياري | يُظهر تلميح حسابات العرض |
| `PORT` | يضبطه Render | يقرأه `wsgi.py` |

**لا يوجد أي سر داخل المستودع.** `render.yaml` يحتوي مراجع فقط.

## حدود الطبقة المجانية — كما ستختبرينها فعلاً

| البند | الواقع |
|---|---|
| سكون الخدمة | تنام بعد **١٥ دقيقة** بلا زيارات |
| زمن الاستيقاظ | **~دقيقة** للطلب الأول بعد النوم |
| ساعات مجانية | ٧٥٠ ساعة/شهر لكل مساحة عمل |
| عمر القاعدة | **٣٠ يوماً** ثم مهلة ١٤ يوماً ثم حذف نهائي |
| سعة القاعدة | ١ جيجابايت |
| نسخ احتياطي | **لا يوجد** |
| PITR | **لا يوجد** |
| استعادة بعد تلف | **مستحيلة** — لا يوجد ما تُستعاد منه |
| مجمّع اتصالات مُدار | غير متاح (لدينا مجمّع داخل التطبيق) |
| إعادة تشغيل مفاجئة | Render قد يعيد تشغيل القاعدة أو يصيّنها في أي وقت |
| نظام الملفات | مؤقت — يُمحى عند كل نشر أو استيقاظ |

**نتيجة عملية:** أول موظف يفتح النظام صباحاً سينتظر نحو دقيقة. والبيانات المالية
لا يجوز أن تعيش هنا: القاعدة ستُحذف بعد ٣٠ يوماً بلا استثناء.

## الترقية للإنتاج لاحقاً

في `render.yaml` غيّري `plan: free` إلى `starter` للخدمة و`basic-256mb` أو أعلى
للقاعدة. عندها فقط تحصلين على PITR ونسخ احتياطي واستمرارية بلا سكون.
**رحّلي البيانات قبل يوم ٣٠، لا بعده.**

## لماذا لا يعتمد التطبيق على نظام الملفات

كل البيانات المالية في PostgreSQL. مفتاح الجلسة من متغيّر بيئة.
لا SQLite ولا ملفات محلية في المسار السحابي — وهذا مُختبَر:
إعادة نشر الخدمة لا تفقد أي بيان.
