# Mabee3at Desktop — نظام إدارة المبيعات لسطح المكتب (ويندوز)

غلاف Electron لتطبيق نظام إدارة المبيعات. **لم يُغيَّر أي شيء في التطبيق نفسه**:
نفس منطق الأعمال، ونفس المستخدمين والصلاحيات، ونفس قاعدة البيانات، ونفس الشاشات.
هذا المشروع يشغّل التطبيق القائم ويعرضه في نافذة سطح مكتب عادية.


---

## أسرع طريقة: التشغيل في المتصفح (بلا تثبيت ولا بناء)

1. فك ضغط المجلد في مكان ثابت، مثلاً `C:\Mabee3at`.
2. **انقر نقرة مزدوجة على `Start-Mabee3at.bat`**.
3. تفتح نافذة سوداء، ويفتح المتصفح تلقائياً على البرنامج خلال ثوانٍ.
4. **اترك النافذة السوداء مفتوحة أثناء العمل.** إغلاقها يوقف البرنامج.

مرة واحدة فقط. بعدها كل يوم: نقرة مزدوجة على نفس الملف وخلاص.
لا `npm` ولا بناء ولا تثبيت بايثون — بيئة التشغيل مضمّنة داخل المجلد.

### اختصار على سطح المكتب

زر الفأرة الأيمن على `Start-Mabee3at.bat` ← **إرسال إلى** ← **سطح المكتب (إنشاء اختصار)**.
بعدها شغّل البرنامج من أيقونة سطح المكتب مباشرة.

### العنوان

البرنامج يفتح على `http://127.0.0.1:5000/` ويمكنك حفظه في المفضلة.
لو كان المنفذ 5000 مشغولاً ببرنامج آخر، ينتقل تلقائياً إلى 5001 وهكذا،
والعنوان الفعلي يظهر في النافذة السوداء.

### لو فتحتِ `index.html` مباشرة بالمتصفح

سترين رسالة "تعذّر بدء التشغيل" — هذا طبيعي، لأن `index.html` هو واجهة إقلاع
تطبيق سطح المكتب وليس البرنامج نفسه. في هذه الحالة اضغطي زر
**«البحث عن البرنامج وفتحه»**: إن كان الخادم يعمل ستُنقلين إليه مباشرة،
وإن لم يكن، شغّلي `Start-Mabee3at.bat` أولاً.

### قاعدة بيانات مشتركة بين أكثر من جهاز

افتحي `Start-Mabee3at.bat` بالمفكرة وأزيلي `rem` من السطر:

```bat
set "SALES_DB=\\SERVER\Shared\Mabee3at\sales.db"
```

مع تنبيه SQLite على الشبكة المذكور في قسم قاعدة البيانات أدناه.

إن أردتِ أيقونة ونافذة تطبيق حقيقية بدل المتصفح، تابعي خطوات البناء التالية.

---

## المرحلة الأولى: سلامة التزامن (منفَّذة)

عُدِّلت طبقة قاعدة البيانات فقط — **بدون أي تغيير في قواعد العمولة أو البونص أو FIFO
أو دورة الشيك أو المسارات أو القوالب**.

| ما تغيّر | لماذا |
|---|---|
| `PRAGMA journal_mode = WAL` | القرّاء لا يعطّلون الكاتب |
| `PRAGMA busy_timeout = 15s` | الكاتب الثاني ينتظر بدل أن يفشل |
| `isolation_level = None` + `BEGIN IMMEDIATE` | قفل كتابة حصري في مقدمة كل عملية مالية |
| تحديثات شرطية بفحص `rowcount` | لا كتابة فوق رصيد تغيّر بين القراءة والكتابة |
| `rollback()` عند أي خطأ | لا كتابات جزئية |
| حارس المهمة اليومية أصبح ذرّياً | لا قيود عكس مكررة لو شُغّلت من جهازين |

**الإثبات:** قبل الإصلاح، محاسبان متزامنان على فاتورة بـ١٢,٢٦٤ جنيهاً أنتجا تحصيلاً
بـ٢٢,٥٦٤ بلا أي رسالة خطأ. بعد الإصلاح، ثمانية محاسبين متزامنين: انخفاض الأرصدة
١٥,١٧٥ والتخصيصات ١٥,١٧٥ بالضبط، صفر تحصيل زائد وصفر أرقام مرجعية مكررة.

الاختبارات ارتفعت من ٦٣ إلى **٦٩**، منها ثلاثة أقسام جديدة تحرس هذا الإصلاح.

> ملاحظة: هذه المرحلة تجعل التزامن سليماً على **خادم واحد**. لا تجعل SQLite صالحة
> للمشاركة عبر مجلد شبكة — تلك تبقى معمارية غير مقبولة للإنتاج.

## متطلبات جهاز المستخدم

**لا شيء.** لا يحتاج المستخدم إلى تثبيت بايثون ولا أي شيء آخر.

- **بيئة تشغيل بايثون مضمّنة** في `runtime/python-win-x64/` — نسخة CPython 3.12.14
  مستقلة لويندوز x64، تعمل بلا تسجيل في النظام وبلا تعارض مع أي بايثون آخر.
- **مكتبات التطبيق مضمّنة** في `vendor/` (Flask وتوابعه) — لا حاجة لـ `pip install`.
- **قاعدة البيانات محلية** — لا خادم ولا سحابة.

الترتيب الذي يتبعه `main.js` عند البحث عن المفسّر:

1. `MABEE3AT_PYTHON` إن حُدِّد صراحةً.
2. **النسخة المضمّنة** `runtime\python-win-x64\python.exe` ← الحالة الطبيعية.
3. بايثون مثبّت على الجهاز — احتياطي فقط، إن فُقدت النسخة المضمّنة.

النسخة المضمّنة تعمل بخيار `-s` مع `PYTHONNOUSERSITE=1` وبلا `PYTHONHOME`،
فلا تلتقط أي حزم من تثبيت بايثون آخر على الجهاز ولا تتأثر به.

### حجم الحزمة

بيئة التشغيل المضمّنة تضيف نحو **٣٩ ميجابايت**، والمثبّت النهائي في حدود
**٩٠–١١٠ ميجابايت** بعد الضغط. هذا ثمن ألا يضطر أي مستخدم لتثبيت شيء.

## التطوير والبناء على ويندوز

> **مهم:** استخدم `npm.cmd` وليس `npm` — سياسة تنفيذ PowerShell قد تمنع تشغيل `npm.ps1`.

1. فك ضغط ملف ZIP.
2. افتح مجلد المشروع.
3. افتح PowerShell داخل هذا المجلد (Shift + زر الفأرة الأيمن ← *Open PowerShell window here*).
4. ثبّت التبعيات:

   ```powershell
   npm.cmd install
   ```

5. شغّل اختبارات التحزيم:

   ```powershell
   npm.cmd test
   ```

6. شغّل تطبيق سطح المكتب للتجربة:

   ```powershell
   npm.cmd start
   ```

7. ابنِ مثبّت ويندوز:

   ```powershell
   npm.cmd run build:win
   ```

8. افتح مجلد `release\`.
9. شغّل ملف `.exe` الناتج لتثبيت البرنامج أو تشغيله.

### أوامر البناء المتاحة

| الأمر | الناتج في `release\` |
|---|---|
| `npm.cmd run build:win` | `Mabee3at Setup 2.0.0.exe` — مثبّت NSIS |
| `npm.cmd run build:win:portable` | `Mabee3at 2.0.0 Portable.exe` — نسخة محمولة بلا تثبيت |
| `npm.cmd run build:win:all` | الاثنان معاً |
| `npm.cmd run clean` | يحذف `release\` فقط — **لا يمس `dist\` إطلاقاً** |

الهدف: **Windows x64**.

### تحذير SmartScreen

المثبّت **غير موقَّع رقمياً** (لا توجد شهادة توقيع متاحة). عند أول تشغيل قد يعرض
ويندوز نافذة زرقاء "Windows protected your PC". اضغط **More info** ثم
**Run anyway**. لإزالة التحذير نهائياً تحتاج شهادة Code Signing من جهة معتمدة،
وعندها تُضاف بيانات الشهادة إلى قسم `build.win` في `package.json`.

## هل يحتاج البرنامج إنترنت؟

**لا، إطلاقاً.** التطبيق يعمل بالكامل بلا اتصال:

- لا يوجد أي backend سحابي (لا Supabase ولا Firebase ولا أي واجهة برمجية خارجية).
- قاعدة البيانات SQLite محلية، وبيئة تشغيل بايثون مضمّنة.
- الخطوط والأنماط محلية داخل الحزمة.

الإنترنت مطلوب مرة واحدة فقط على **جهاز البناء** عند `npm.cmd install`.
أجهزة المستخدمين لا تحتاجه لا عند التثبيت ولا عند التشغيل.

---

## أي قاعدة بيانات يستخدمها البرنامج؟

**SQLite** في ملف واحد. هذا هو التصميم الأصلي للنظام ولم يُغيَّر.

ترتيب تحديد مسار القاعدة:

1. متغيّر البيئة `SALES_DB` إن كان محدَّداً — **له الأولوية دائماً**.
2. وإلا: مجلد بيانات المستخدم
   `C:\Users\<اسمك>\AppData\Roaming\Mabee3at\data\sales.db`

عند أول تشغيل بعد التثبيت تُنسخ القاعدة المرفقة مع الحزمة إلى مجلد المستخدم،
لأن مجلد Program Files للقراءة فقط.

> **انتبه:** القاعدة المرفقة في `data\sales.db` هي قاعدة النظام الحالية بمحتواها
> التجريبي (المستخدمون `admin` / `accountant` / `rep1` / `rep2` بكلمة مرور `123456`).
> قبل الاستخدام الفعلي: **غيّر كلمات المرور**، وضع مكانها قاعدة بياناتكم الحقيقية.

### هل يشترك عدة مستخدمين في نفس القاعدة؟

النظام نفسه متعدد المستخدمين (مدير / محاسب / مندوب)، لكن هذا الغلاف يشغّل نسخة
خادم محلية داخل جهاز كل مستخدم. لذلك **افتراضياً لكل جهاز قاعدته الخاصة**.

للمشاركة الحقيقية بين عدة أجهزة أمامك خياران:

**أ) مجلد شبكة مشترك** — الأبسط، ويصلح لعدد قليل من المستخدمين:

```powershell
setx SALES_DB "\\SERVER\Shared\Mabee3at\sales.db"
```

تنبيه: SQLite على مشاركة شبكة SMB لا يتحمل الكتابة المتزامنة الكثيفة، وقد يحدث
تعارض قفل عند الاستخدام المكثف من عدة أجهزة في نفس اللحظة.

**ب) خادم مركزي واحد** — الأنسب لفريق حقيقي: شغّل تطبيق Flask على جهاز خادم واحد،
وليدخل الباقون عبر المتصفح على عنوانه. هذا هو وضع التشغيل الذي صُمم له النظام أصلاً،
وتطبيق سطح المكتب يبقى مفيداً لجهاز واحد أو للعمل بلا شبكة.

---

## كيف تعمل المصادقة؟

كما هي في تطبيق الويب تماماً، بلا أي تغيير:

- تسجيل الدخول باسم مستخدم وكلمة مرور من جدول `users`.
- كلمات المرور مخزَّنة بصيغة hash عبر `werkzeug.security` — لا تُحفظ كنص صريح.
- الجلسة عبر كوكي Flask موقَّع.
- ثلاثة أدوار: **مدير** (كل شيء)، **محاسب** (العمليات دون الإعدادات وسجل التدقيق)،
  **مندوب** (بياناته فقط).
- كل مسار محمي بـ `@login_required` أو `@roles(...)`، والمندوب محصور ببيانات عملائه.

مفتاح توقيع الجلسة يُولَّد عشوائياً عند أول تشغيل ويُحفظ في مجلد بيانات المستخدم
باسم `session.key`. **لا يوجد أي مفتاح أو كلمة مرور مكتوبة داخل الكود.**

## استكشاف الأعطال

**"تعذّر تشغيل بيئة التشغيل المضمّنة"**
مجلد `runtime\python-win-x64` مفقود أو تالف. أعد التثبيت. أو استخدم بايثون على الجهاز:

```powershell
setx MABEE3AT_PYTHON "C:\Python312\python.exe"
```

**مضاد الفيروسات يحجب `python.exe` داخل مجلد البرنامج**
بعض برامج الحماية تعترض المفسّرات المضمّنة. أضف مجلد تثبيت البرنامج إلى الاستثناءات.

**النافذة السوداء تُظهر حروفاً غريبة مكان العربية**
مشكلة عرض فقط ولا تؤثر على البرنامج. المتصفح سيفتح طبيعياً.

**المتصفح لا يفتح تلقائياً**
افتحيه يدوياً على العنوان الظاهر في النافذة السوداء، غالباً `http://127.0.0.1:5000/`.

**البرنامج يفتح ثم تظل شاشة الإقلاع**
اضغط "إعادة المحاولة". لو تكرّر، شغّل من PowerShell بـ `npm.cmd start` لرؤية سجل الخادم.

## تحديث التطبيق مستقبلاً

هذا التطبيق يولّد صفحاته من الخادم (Flask + قوالب Jinja)، لذا التحديث يكون
باستبدال ملفات التطبيق في مجلد `app\` وليس ملف HTML واحد:

```
نسخة معتمدة جديدة من التطبيق
   → استبدل محتويات app\  (وحدّث dist\index.html لو تغيّرت شاشة الإقلاع)
   → npm.cmd test
   → npm.cmd start        ← جرّب قبل البناء
   → npm.cmd run build:win
   → وزّع المثبّت الجديد من release\
```

**لا تحتاج إعادة بناء غلاف Electron من الصفر.** الغلاف (`main.js` و`preload.js`)
مستقل عن التطبيق: يشغّل `app\server.py` أياً كان محتواه ويعرضه.

عند ترقية قاعدة بيانات قائمة إلى إصدار أحدث من المخطط:

```powershell
cd app
python migrate.py
```

خذ نسخة احتياطية من ملف `sales.db` قبل الترحيل.

## الأمان في غلاف سطح المكتب

- `contextIsolation: true` و `nodeIntegration: false` و `sandbox: true`.
- `preload.js` لا يمرّر أي وحدة Node إلى الصفحة؛ يكشف أربع دوال فقط:
  حالة الإقلاع، معلومات النسخة، إعادة المحاولة، والإغلاق.
- الخادم يستمع على `127.0.0.1` فقط على منفذ حر يُختار عند التشغيل — غير متاح للشبكة.
- أي رابط خارج التطبيق يُفتح في المتصفح لا داخل النافذة.
- `debug=False` دائماً، فلا يعمل مصحّح Werkzeug التفاعلي.

> ملاحظة تشغيلية: خادم Flask المدمج هو خادم تطوير. لجهاز واحد بمستخدم واحد هذا مقبول.
> للتشغيل المركزي متعدد المستخدمين استخدم خادم WSGI مثل waitress.

## اختبارات التحزيم

`npm.cmd test` يشغّل ٣٨ فحصاً بلا أي تبعيات خارجية، وتغطي:

1. وجود `dist/index.html` وأنه غير فارغ وسليم البنية.
2. صحة `main.js` و`preload.js` نحوياً، وأن النافذة تحمّل `dist/index.html`.
3. إعدادات الأمان (العزل، تعطيل Node، الصندوق الرملي، حدود جسر preload).
4. صحة `package.json` ووجود كل الأوامر المطلوبة.
5. **عدم وجود أي أمر أو سكربت يحذف مجلد المصدر `dist/`**.
6. صحة إعداد electron-builder: هدف NSIS ومحمول، x64، والمخرجات في `release/`.
7. اكتمال ملفات التطبيق: ملفات بايثون، ٣٠ قالباً، ملف الأنماط، ومكتبات `vendor/`
   خالية من أي ملفات ثنائية خاصة بمنصّة أخرى.
8. وجود بيئة التشغيل المضمّنة وأنها ملف تنفيذي ويندوز حقيقي (توقيع PE)،
   وأنها تحوي `sqlite3` و`hashlib` وباقي ما يحتاجه التطبيق،
   وأن `main.js` يفضّلها على أي بايثون مثبّت.
9. أن إعداد قاعدة البيانات ما زال الحقيقي ولم يُستبدل بنسخة تجريبية، وأن المصادقة
   والأدوار ومنطق الأعمال لم تُمس.
10. عدم تسرّب أي مفاتيح خدمة أو كلمات مرور أو شهادات خاصة داخل ملفات الحزمة.
